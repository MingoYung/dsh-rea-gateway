# 测量结果与适用范围

[English](benchmark.en.md) · [机器可读数据](benchmark.json) · [项目说明](../README.md)

测量日期：2026-10-31。以下区分模型侧 token 计数和工具定义 JSON 的字节数；两种单位不能互换。这里只公开脱敏数字与方法，原始私有请求、聊天记录、模型配置和机器路径不随仓库发布，因此仓库本身不能逐字重现私有样本。

## 一次失败请求的配对计数

该样本使用 REA `6.5.0`，包含 207 个 REA MCP 工具定义。

| 项目 | 模型侧计数 |
| --- | ---: |
| 原始失败错误报告的 prompt | 287,065 tokens |
| 重建请求，保留全部工具定义 | 284,483 tokens |
| 同一重建请求，只移除 REA 工具定义 | 34,239 tokens |
| 两个重建请求的差额 | **250,244 tokens** |
| 原始报错比完整重建请求多出的数量 | **2,582 tokens，原因未确定** |

计数使用该次部署的 **Strata 服务提供的 `POST /v1/messages/count_tokens`**。这是被测服务提供的接口，不是对所有 OpenAI 兼容服务的通用假设。

重建方法：

1. 从失败请求的 DSH 输入快照恢复系统内容、五项用户侧内容及工具定义，构造 Anthropic 风格的计数请求。
2. 工具字段按 `name`、`description`、`parameters → input_schema` 映射。保留完整系统与消息内容，调用服务的计数接口。
3. 服务通过实际 Qwen tokenizer 与聊天模板执行提示词编码，使用 `encode_prompt(store=False)`；这一步包括工具与模板渲染，不执行模型推理。
4. 复制完全相同的计数请求，只从 `tools` 数组移除 REA 的 207 项定义，再走相同接口与编码路径。差值为 `284483 - 34239 = 250244`。

这个配对比较支持“REA 工具定义使该重建请求增加了约 25 万输入 tokens”的结论。它不证明原始请求已被逐字恢复；原始错误与完整重建之间的 2,582 tokens 差异仍未解释，不能把重建数字替换成原始错误数字。

若后续请求再次完整附带相同定义，可能重复产生同量级的输入负担。精确数量会随 tokenizer、聊天模板、REA 版本、序列化和其他请求内容变化。缓存命中可能改变计费、处理成本或延迟；本次没有测量费用节省，也没有证明每次请求都必然减少 250,244 个计费 tokens。

## 本地适配版的受控集成验收

这一组使用公开分支形成前的本地适配版 `0.1.4-local.1`，上游基础为 `kirkchinese/dsh-capability-catalog 0.1.4`。其三个入口仍名为 `capability_search`、`capability_describe`、`capability_call`。

在干净、独立的 DSH headless profile 中安装实际构建 tarball，通过 DSH Desktop 的 CLI 启动。模型请求全部发到本机 HTTP 假端点，返回固定文本或预先编排的工具调用；没有执行真实模型推理。REA 调用连接真实的固定版本 `rea-agents@6.5.0`。

| 观察项 | 结果 |
| --- | ---: |
| 截获的模型 HTTP 请求 | 13 次 |
| REA 网关入口 | 3 个 |
| 三个入口在 OpenAI 工具数组中的 JSON 大小 | 2,098 UTF-8 字节 |
| 该 headless profile 原生工具 | 25 个 |
| 启用网关后的总工具 | 28 个 |
| 全部 28 个工具 JSON 大小 | 23,712 UTF-8 字节 |
| 请求工具数组中的原始 REA 工具 | 0 个 |

检索、查看参数和调用之后，三个入口的定义体积保持不变。这里的 25 / 28 仅描述该 headless profile，不能推广为用户桌面环境的总工具数。

通过的用例包括：

- 原生 `pwsh` 执行无副作用的工作目录读取。
- `search → describe → call` 完整链路与真实 REA `binary_session({})` 只读调用。
- REA 全局关闭时拒绝调用。
- 会话关闭覆盖全局开启，调用被拒绝。
- 会话开启覆盖全局关闭，真实 REA 调用成功。
- 网关总开关关闭时，三个入口从模型请求中移除。

开关状态由插件自己的状态文件预置，再经真实 DSH 分发验证；这组测试没有覆盖浏览器控件的鼠标点击流程。假端点提供的 usage 是测试固定值，未用来计算真实 tokens、模型速度或成本。

## 公开版的独立命名

公开包 `dsh-rea-gateway@0.1.0` 使用 `rea_search`、`rea_describe`、`rea_call`，以及独立的 `reaGateway` 远程服务命名空间。上面 2,098 字节来自旧名字的本地适配版，不能直接标作公开版实测大小。

公开包已在干净的 DSH headless profile 中安装实际 tarball，并通过本机假模型端点完成 6 个用例，共截获 12 次请求。普通请求、`rea_search → rea_describe → rea_call` 与真实 REA 只读调用、全局关闭、会话关闭覆盖全局开启、会话开启覆盖全局关闭、网关总开关关闭均通过。实际服务身份确认为 REA 6.5.0；所有用例退出码为 0，stderr 为空。

| 公开版 `0.1.0` 观察项 | 结果 |
| --- | ---: |
| 通过的用例 | 6 个 |
| 截获的模型 HTTP 请求 | 12 次 |
| `rea_*` 入口在 OpenAI 工具数组中的 JSON 大小 | 2,063 UTF-8 字节，每轮相同 |
| 全部 28 个工具 JSON 大小 | 23,677 UTF-8 字节 |
| 该 headless profile 原生工具 | 25 个 |
| 请求工具数组中的原始 REA 工具 | 0 个 |

全局关闭和会话关闭都实际拒绝 `rea_call` 并隐藏对应索引；会话开启可覆盖全局关闭并完成真实 REA 调用。总开关关闭时没有网关入口，只保留 25 个原生工具。开关状态通过插件状态文件预置后经真实 DSH 分发验证，这次 headless 验收没有点击浏览器控件。

公开工具的 `{name, description, parameters}` 定义 JSON 另测得 1,970 UTF-8 字节。这是定义对象序列化的字节数，2,063 字节则包含实际 OpenAI 工具数组的封装；两者都不是模型 token 数。数据见 [benchmark.json](benchmark.json) 的 `public_release` 项与 [公开版集成结果](public-integration.json)。

## 在自己的部署上复核

1. 固定 DSH、REA、模型服务与插件版本，并保留 tokenizer、聊天模板及相关请求设置。
2. 采集一次实际发出的请求，分别记录系统、消息和工具定义；在公开任何材料前移除私有内容与凭证。
3. 使用实际模型服务认可的 tokenizer 和完整模板做配对计数：完整请求与仅移除 REA 定义的请求。不要以字符数、文件大小或另一个模型的 tokenizer 替代。
4. 安装并启用网关、关闭旧的 REA 直连注册，核对工具数组中存在三个 `rea_*` 入口，且没有 `mcp__rea__*` 全量工具。
5. 分别测量普通请求与按需调用之后的请求，并测试全局、会话开关。费用或延迟结论需要另外测量缓存状态、账单规则与运行时间。

以上属于特定样本的上下文体积核验与功能集成验收，没有评估模型回答质量、逆向分析质量或所有 REA 工具的可用性。
